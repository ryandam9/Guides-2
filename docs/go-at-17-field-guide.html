Go at 17: one year of changes, in code

This guide shows each change from the Go 17th birthday post as code. Where a change replaces an old pattern, you see the code before and after.

Releases: Go 1.26 (February), Go 1.27 (August)Source: go.dev/blog/17yearsWritten by: Claude Opus 5.5

How to read this guide

ExplanationsA box below each example tells you what the code does and describes its data structures. Go experience is not necessary.

Basic terms

The explanations use these terms. Read them first if you are new to programming.

PackageA group of Go files with one purpose. import lets your file use a package. fmt prints text. time works with time.
VariableA name for a value in memory. x := 3 declares the variable x and gives it the value 3.
TypeThe kind of a value. int is a whole number. string is text. bool is true or false. byte is one unit of raw data.
FunctionA named block of code. It accepts inputs and returns results. The program starts in func main().
MethodA function that belongs to a type. You call it with a dot: value.Method().
StructA group of named fields that make one value, for example a user with an ID and a name.
PointerThe address of a value in memory. *int is a pointer to an int. &x is the address of x. nil means no value.
SliceAn ordered list that can grow. []int is a slice of whole numbers. append adds an item.
MapA table that finds a value from a key. map[string]int finds a whole number from text.
InterfaceA list of methods. Each type that has those methods can be used where the interface is necessary.
GenericCode with a placeholder for a type, written in square brackets: [T any]. One function then works for many types.
ErrorA value that tells you that an operation failed. A function returns it as its last result. nil means no error.
GoroutineA function that runs at the same time as other code. The word go starts it.
ChannelA pipe between goroutines. One goroutine sends a value and a different goroutine receives it.
CommentText after //. It is for the reader. The compiler ignores it.

1

Language

Five changes. Each change removes a workaround. Old code continues to compile.

1.1

new with a value

Go 1.26

The built-in function new now accepts an expression. The expression gives the initial value of the variable.

Use this change for optional fields that are pointers. JSON and protocol buffer structures frequently have such fields.

Before Go 1.26
type Patch struct {
	Name    *string `json:"name,omitempty"`
	Retries *int    `json:"retries,omitempty"`
}

// A helper function was necessary.
func ptr[T any](v T) *T { return &v }

func main() {
	p := Patch{
		Name:    ptr("payments"),
		Retries: ptr(3),
	}
	_ = p
}
Go 1.26
type Patch struct {
	Name    *string `json:"name,omitempty"`
	Retries *int    `json:"retries,omitempty"`
}

func main() {
	p := Patch{
		Name:    new("payments"), // *string
		Retries: new(3),          // *int
	}
	// An expression is also permitted.
	deadline := new(time.Now().Add(time.Hour)) // *time.Time
	_, _ = p, deadline
}

What the code does

The two programs make a Patch value. A Patch describes a change to a record. Each field is optional: you fill only the fields that you want to change.

The old program needs a small helper function, ptr. It accepts a value and gives back the address of a copy of that value. The new program uses the built-in function new for the same work. new("payments") makes a new text variable that contains payments and gives you its address.

The line with deadline makes a pointer to a time that is one hour from now.

Data structures
  • Patch is a struct: a group of named fields. It has the fields Name and Retries.
  • *string and *int are pointer types. A pointer holds the address of a value. A pointer can also be nil, which means that there is no value. A plain int cannot show the difference between 0 and "not given". A pointer can.
  • The text in backquotes after each field is a struct tag. It tells the JSON package which name to use for the field. omitempty tells it to leave out the field when the field is empty.
  • ptr[T any] is a generic function. T is a placeholder for a type. Thus one function works for text, numbers and all other types.

NOTE new(T) with a type continues to work. new(3) makes a pointer to an int variable with the value 3.

1.2

Type constraints that refer to themselves

Go 1.26

A generic type can now refer to itself in its type parameter list.

You can write a constraint that says: the method accepts the same type and returns the same type.

Before Go 1.26
// Compile error before Go 1.26:
// Adder refers to itself in its type parameter list.
//
//   type Adder[A Adder[A]] interface { Add(A) A }

// Workaround: write the constraint again
// in each function.
func Sum[A interface{ Add(A) A }](xs ...A) A {
	var total A
	for _, x := range xs {
		total = total.Add(x)
	}
	return total
}
Go 1.26
type Adder[A Adder[A]] interface {
	Add(A) A
}

type Cents int64

func (c Cents) Add(d Cents) Cents { return c + d }

func Sum[A Adder[A]](xs ...A) A {
	var total A
	for _, x := range xs {
		total = total.Add(x)
	}
	return total
}

func main() {
	fmt.Println(Sum(Cents(250), Cents(199))) // 449
}

What the code does

Sum adds a list of values and returns the total. It works for each type that has an Add method. The loop starts with an empty total. Then it adds the values one at a time.

The program adds 250 cents and 199 cents and prints 449.

In the old code, the rule "the type has an Add method" is in the declaration of Sum. You write it again in each function that needs it. In the new code the rule has a name, Adder, and each function can use that name.

Data structures
  • Cents is a new type that holds an int64, a whole number of 64 bits. Money in cents has no fractions, thus the arithmetic is exact.
  • func (c Cents) Add(d Cents) Cents is a method: a function that belongs to the type Cents. You call it with a dot: total.Add(x).
  • Adder[A] is an interface: a list of methods that a type must have. This one says: type A has a method Add that accepts an A and returns an A. The interface uses its own name in its declaration. That was not permitted before Go 1.26.
  • xs ...A lets the caller give any number of values. In the function, xs is a slice: an ordered list.
  • var total A makes a variable with the zero value of its type. For a number type, the zero value is 0.
1.3

Generic methods

Go 1.27

A method declaration can now have its own type parameters. This limit was in the language from Go 1.18.

Before, a generic operation on a type was a package-level function. Now the operation can be a method of the type.

Before Go 1.27
type Stream[T any] struct{ items []T }

func Of[T any](items ...T) Stream[T] { return Stream[T]{items} }

func (s Stream[T]) Filter(keep func(T) bool) Stream[T] {
	var out []T
	for _, v := range s.items {
		if keep(v) {
			out = append(out, v)
		}
	}
	return Stream[T]{out}
}

// Map changes T to U. A method could not declare U.
func Map[T, U any](s Stream[T], f func(T) U) Stream[U] {
	out := make([]U, 0, len(s.items))
	for _, v := range s.items {
		out = append(out, f(v))
	}
	return Stream[U]{out}
}

func main() {
	isEven := func(n int) bool { return n%2 == 0 }
	s := Map(Of(1, 2, 3, 4).Filter(isEven), strconv.Itoa)
	fmt.Println(s.items) // [2 4]
}
Go 1.27
type Stream[T any] struct{ items []T }

func Of[T any](items ...T) Stream[T] { return Stream[T]{items} }

	for _, v := range s.items {
		if keep(v) {
			out = append(out, v)
		}
	}
	return Stream[T]{out}
}

// The method declares its own type parameter U.
func (s Stream[T]) Map[U any](f func(T) U) Stream[U] {
	out := make([]U, 0, len(s.items))
	for _, v := range s.items {
		out = append(out, f(v))
	}
	return Stream[U]{out}
}

What the code does

The program makes a stream that holds the numbers 1, 2, 3 and 4. It keeps the even numbers (2 and 4). Then it changes each number to text. It prints [2 4].

Filter looks at each item and keeps it only if the function keep returns true. Map calls the function f on each item and collects the results.

Map changes the item type, here from number to text. Thus it needs a second type placeholder, U. In the old code a method could not declare U, so Map was a separate function and the call reads from the inside out. In the new code Map is a method and the steps read from left to right.

Data structures
  • Stream[T] is a generic struct. It has one field, items, which is a slice of T. Stream[int] holds whole numbers. Stream[string] holds text.
  • func(T) bool is a function type. In Go you can give a function to a different function as an argument. isEven and strconv.Itoa are used in this way.
  • strconv.Itoa changes a whole number to text: 2 becomes "2".
  • make([]U, 0, len(s.items)) makes an empty slice with space for all the results. append adds one item to the end of a slice.
  • n%2 == 0 is true when the remainder of n divided by 2 is zero, thus when n is even.

The standard library uses the feature. math/rand/v2 has a new generic method Rand.N.

Before Go 1.27
r := rand.New(rand.NewPCG(1, 2))

// Convert to int64, then convert back.
wait := time.Duration(r.Int64N(int64(5 * time.Second)))
Go 1.27
r := rand.New(rand.NewPCG(1, 2))

// N accepts each integer type.
wait := r.N(5 * time.Second) // time.Duration

What the code does

The code selects a random wait time that is less than 5 seconds. Programs do this, for example, before they try a failed request again.

The old method Int64N accepts only the type int64. Thus you change the duration to int64 and then change the result back. The new method N accepts each whole-number type and returns the same type.

Data structures
  • r is a random number generator. rand.NewPCG(1, 2) is its source. The numbers 1 and 2 are the seed. The same seed always gives the same sequence of numbers, which is useful in tests.
  • time.Duration is a length of time. Go stores it as a whole number of nanoseconds. 5 * time.Second is five seconds.
  • := declares a variable and gives it a value in one step.

CAUTION An interface method cannot have type parameters. A generic method cannot implement an interface method.

1.4

More type inference for generic functions

Go 1.27

The compiler now infers type arguments in each context where you assign a generic function to a matching function type.

This includes conversions and composite literals.

Before Go 1.27
func first[T any](s []T) T { return s[0] }
func last[T any](s []T) T  { return s[len(s)-1] }

// The type arguments were necessary.
ops := []func([]int) int{first[int], last[int]}
Go 1.27
func first[T any](s []T) T { return s[0] }
func last[T any](s []T) T  { return s[len(s)-1] }

// The element type gives T = int.
ops := []func([]int) int{first, last}
Complete program and output
main.go · needs Go 1.27 or later
package main

import "fmt"

func first[T any](s []T) T { return s[0] }
func last[T any](s []T) T  { return s[len(s)-1] }

func main() {
	// The element type gives T = int.
	ops := []func([]int) int{first, last}

	nums := []int{10, 20, 30}
	for _, op := range ops {
		fmt.Println(op(nums))
	}
}

$ go run .
10

What the code does

first returns the first item of a list. last returns the last item. They are generic: they work for a list of any type.

The last line puts the two functions into a list with the name ops. In the old code you had to write first[int] to say that the type is int. In the new code the compiler finds the type from the type of the list.

Data structures
  • []func([]int) int is a slice of functions. Each function in it accepts a slice of whole numbers and returns one whole number. A function is a value in Go: you can keep it in a variable or in a list.
  • s[0] is the first item of the slice s. Positions start at 0. len(s) is the number of items, thus s[len(s)-1] is the last item.
1.5

Struct literal keys for embedded fields

Go 1.27

A key in a struct literal can now be a field selector of the struct type. Before, only a top-level field name was permitted.

You can set a promoted field directly. You do not write the embedded type again.

Before Go 1.27
type Base struct {
	ID      int
	Created time.Time
}

type User struct {
	Base
	Name string
}

u := User{
	Base: Base{ID: 7},
	Name: "Mittens",
}
Go 1.27
type Base struct {
	ID      int
	Created time.Time
}

type User struct {
	Base
	Name string
}

u := User{
	ID:   7, // promoted from Base
	Name: "Mittens",
}
Complete program and output

What the code does

The code makes a User with the ID 7 and the name Mittens.

Data structures
  • Base is a struct with two fields: ID (a whole number) and Created (a moment in time, of type time.Time).
  • User is a struct that embeds Base. To embed, you write the type with no field name. Then User gets the fields of Base. You can write u.ID. Such a field is called a promoted field.
  • The code does not set Created. It keeps its zero value.
  • User{...} is a composite literal: it makes a struct value and fills the fields that you name.

Standard library

A new JSON engine, a leak profiler, faster HTTP/1 clients, and three new APIs.

2.1

encoding/json/v2 and jsontext

Go 1.276 years of work

Go 1.27 has two new packages. encoding/json/v2 changes Go values to JSON and back. encoding/json/jsontext reads and writes JSON tokens without reflection.

The old package encoding/json now uses the v2 engine. Your code gets faster unmarshal operations and you do not change it. The blog post gives a maximum of 10 times.

Stricter defaults

Version 1 accepts input that can hide errors or attacks. Version 2 rejects this input.

package main

import (
	"encoding/json"
	"fmt"
)

type Account struct {
	ID   string   `json:"id"`
	Role string   `json:"role"`
	Tags []string `json:"tags"`
}

func main() {
	in := []byte(`{"id":"a1","role":"viewer","ROLE":"admin"}`)

	var a Account
	err := json.Unmarshal(in, &a)
	fmt.Println(a.Role, err) // admin <nil>

	fmt.Println(string(out))

}

What the code does

JSON is a text format for data. Programs use it to send data to other programs. Each program does two steps. First it reads JSON text into an Account (this is "unmarshal"). Then it writes an Account as JSON text (this is "marshal").

The input has two members with almost the same name: "role":"viewer" and "ROLE":"admin". Version 1 ignores the difference between capital and small letters. The second member replaces the first, and the role becomes admin. An attacker can use this to hide a value. Version 2 accepts only the exact name, and the role stays viewer.

In the output, Tags has no items. Version 1 writes null. Version 2 writes an empty list, [].

Data structures
  • Account is a struct with three fields. The struct tags give the JSON name of each field.
  • []byte is a slice of bytes: raw data. The JSON functions read bytes and write bytes. string(out) changes bytes to text for the print.
  • &a is the address of the variable a. Unmarshal needs the address to put the data into a.
  • Tags []string is a slice of text values. It is nil when nothing was put into it.
  • err is an error value. nil means that there was no error. out, _ := puts the first result in out and discards the second.

Options at the call site

Each v2 function accepts options. The caller controls the behavior for one call. In version 1 you made a Decoder or a wrapper type.

Version 1
// Reject unknown fields: a Decoder was necessary.
dec := json.NewDecoder(r)
dec.DisallowUnknownFields()
err := dec.Decode(&cfg)

// Unix time for time.Time: a wrapper type
// with a MarshalJSON method was necessary.
type unixTime time.Time

func (t unixTime) MarshalJSON() ([]byte, error) {
	return strconv.AppendInt(nil, time.Time(t).Unix(), 10), nil
}
Version 2
// Reject unknown members with one option.
err := json.UnmarshalRead(r, &cfg,
	json.RejectUnknownMembers(true))

// The caller gives a marshal function for time.Time.
// The struct types do not change.
unix := json.MarshalFunc(func(t time.Time) ([]byte, error) {
	return strconv.AppendInt(nil, t.Unix(), 10), nil
})
out, err := json.Marshal(event, json.WithMarshalers(unix))

What the code does

The code shows two tasks.

Task 1: read a configuration and stop with an error if the input has a name that the struct does not have. This finds typing errors in configuration files.

Task 2: write a time as Unix seconds (the number of seconds from 1 January 1970) and not as date text.

In version 1 you make a Decoder object and change its setting for task 1. For task 2 you make a new type with its own method. In version 2 you give options to the function call. Your types do not change.

Data structures
  • r is a reader: a source of bytes, for example a file or a network connection.
  • cfg is the struct that gets the data. &cfg is its address.
  • dec is a Decoder. It reads JSON from the reader.
  • unixTime is a new type made from time.Time. Its method MarshalJSON tells the JSON package how to write the value.

package main

import (
	"errors"
	"os"
	"runtime/pprof"
	"time"
)

func fetch(id int) error {
	if id == 0 {
		return errors.New("id 0 failed")
	}
	time.Sleep(10 * time.Millisecond)
	return nil
}

func fetchAll(ids []int) error {
	ch := make(chan error) // unbuffered
	for _, id := range ids {
		go func() { ch <- fetch(id) }()
	}
	for range ids {
		if err := <-ch; err != nil {
			return err // the other senders block
		}
	}
	return nil
}

}

What the code does

fetchAll starts one goroutine for each ID. A goroutine is a function that runs at the same time as the other code. Each goroutine calls fetch and sends the result into the channel ch.

fetchAll reads the results. ID 0 fails, and fetchAll returns at that first error. The three other goroutines still want to send their results. Nothing reads the channel, thus they wait until the program stops. This is a leak.

Data structures

  • go func() { ... }() starts a goroutine.
  • []int{0, 1, 2, 3} is a slice of four whole numbers: the IDs.
  • errors.New("...") makes an error value with a message. time.Sleep stops the goroutine for the given time.
  • pprof.Lookup(name) gets a profile: a report from the Go runtime about the program. WriteTo(os.Stdout, 1) prints it on the terminal.

To correct this leak, give the channel a buffer: ch := make(chan error, len(ids)). Then each sender completes.

Go 1.26

	"crypto/hpke"
	"fmt"
	"log"

func main() {
	kem := hpke.MLKEM768X25519() // post-quantum hybrid KEM
	kdf := hpke.HKDFSHA256()
	aead := hpke.AES256GCM()

	// Recipient: make a key pair.
	priv, err := kem.GenerateKey()
	if err != nil {
		log.Fatal(err)
	}

	info := []byte("orders-v1")
	ct, err := hpke.Seal(priv.PublicKey(), kdf, aead, info, []byte("hello"))
	if err != nil {
		log.Fatal(err)
	}

	// Recipient: decrypt.
	pt, err := hpke.Open(priv, kdf, aead, info, ct)

}

What the code does

A digital signature shows that a message came from the holder of a private key and that nobody changed it. Each block makes a key, signs a message, and examines the signature.

The classical code first calculates a digest: a short fingerprint of the message with a fixed size. Then it signs the digest. The ML-DSA code signs the message directly.

The result of the check is different. ecdsa.VerifyASN1 returns true or false. mldsa.Verify returns an error, and nil means that the signature is correct.

Data structures

  • opts is a pointer to an mldsa.Options struct. Context is a label. Use the same label when you sign and when you examine.
  • rand.Reader is the secure source of random bytes of the system.

What the code does

Two sides calculate a shared secret from a private key and the public key of the other side. Then they make a session key from it.

The shared secret is temporary. It must not stay in memory, where a later defect or a crash report can show it. secret.Do runs the function and then erases the data that the function left in the CPU registers, on the stack and on the heap.

Data structures

  • func() { ... } is a function with no name. It can use the variables of the function around it, here priv and peer.
  • deriveKey is a function from your program. It is not shown.

Upgrade checklist

One sequence for the upgrade to Go 1.27, and the switches that bring back an old behavior.

7.1

Procedure

Go 1.27

Do the steps in this sequence. Each step refers to the section that gives the details.

  1. Install Go 1.27 or later. Make sure with go version.
  2. Set the language version of the module: go mod edit -go=1.27. The new language features of section 1 need this line. With go 1.26 in go.mod, the Go 1.27 compiler rejects them.
  3. Build and examine the code: go build ./... && go vet ./...
  4. Do the tests: go test ./.... If a test compares exact output, look at these three causes first: the text of JSON errors (section 2.1), compressed bytes (section 2.7) and JPEG data (section 2.7).
  5. Find tests that give a fixed random reader to a crypto function. Change them to cryptotest.SetGlobalRandom (section 4.4).
  6. Show the modernizer changes with go fix -diff ./.... Apply them with go fix ./.... Do the tests again (section 5.1).
  7. Examine the code for known vulnerabilities: govulncheck ./... (section 4.6).
  8. Measure. Do your benchmarks with go test -bench=. -benchmem and compare with the values before the upgrade (sections 3.1 and 3.3).
  9. If a step fails, use one switch from section 7.2 to find the cause. Remove the switch when the cause is corrected.

More changes in Go 1.27

These changes are in the Go 1.27 release notes. They are not in the birthday post.

8.1

Small additions to the standard library

Go 1.27

The example shows two of the additions. The list below it gives more.

main.go · needs Go 1.27 or later
package main

import (
	"fmt"
	"net/url"
	"strings"
)

func main() {
	// strings.CutLast divides text at the LAST separator.
	dir, file, found := strings.CutLast("/var/log/app/server.log", "/")
	fmt.Println(dir, file, found)

	// URL.Clone makes a full copy. A change to the copy
	// does not change the original.
	u, _ := url.Parse("https://example.com/search?q=go")
	c := u.Clone()
	c.Path = "/docs"
	fmt.Println(u)
	fmt.Println(c)
}
Terminal · recorded with Go 1.27.4
$ go run .
/var/log/app server.log true
https://example.com/search?q=go
https://example.com/docs?q=go
What the code does

The first part divides a file path into the directory and the file name. strings.CutLast looks for the last /. It returns the text before it, the text after it, and true because it found the separator. The older function strings.Cut uses the first separator.

The second part reads a web address into a URL value and makes a copy with Clone. The program changes the path of the copy. The output shows that the original did not change.

Data structures
  • dir, file and found are three results of one function call. Go functions can return more than one value.
  • u is a pointer to a url.URL: a struct with the parts of a web address, for example Scheme, Host, Path and RawQuery.
  • c is a pointer to a second, independent url.URL. If you write c := u, the two names point to the same struct, and a change through c also changes u. Clone prevents that.
  • u, _ := discards the error result of url.Parse. In a real program, examine the error.
  • bytes.CutLast does the same as strings.CutLast for slices of bytes.
  • url.Values.Clone makes a full copy of a set of query parameters.
  • synctest.Sleep in testing/synctest does a sleep and then waits until the other goroutines of the bubble are blocked.
  • hash/maphash has the new interfaces Hasher and ComparableHasher. They are the base for the generic collections of section 6.1.
  • math/big has Int.Divide. It returns the quotient and the remainder with a rounding mode that you select.
  • database/sql has ConvertAssign. Drivers can use the conversions of Rows.Scan.
  • crypto/tls accepts MLKEM1024 in Config.CurvePreferences. Config.Rand is deprecated. Use cryptotest.SetGlobalRandom in tests.
  • net/http has Server.MaxHeaderValueCount. The HTTP/2 server obeys the priorities that the client sends. Server.DisableClientPriority stops this.
  • The package unicode uses Unicode 17.
